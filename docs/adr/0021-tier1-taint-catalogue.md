# ADR-0021: Tier-1 taint rules from one RiskGraph catalogue; the taint evidence contract

Status: accepted; tier 1 is **off by default** until the owner checks it (F-2-1, L-4) · Date: 2026-10-27 · Implements: expansion phase X4 part 1 (`docs/proposals/EXPANSION_A-D.md` §3.A, §4 X4, §6, §8 decision 6) · Builds on: ADR-0015 (L3 call graph), ADR-0017 (evidence and assurance)

## Context
Plan §3.A makes Semgrep CE's taint mode tier 1: RiskGraph-authored rules for the frameworks the extractor knows, generated from one catalogue that the deep profile (tier 2, Joern) will share. G12: the vendored `semgrep-rules` content may not be copied into RiskGraph's own rules.

## Decision
**Catalogue** `backend/riskgraph/modules/scanners/semgrep/taint_catalogue.yaml`, Apache-2.0, written from each library's documented API:
- Sources per language:
  - Flask `flask.request.*`;
  - Django `request.GET/POST/body/COOKIES/headers`;
  - FastAPI: every parameter of a function decorated as a route (`@$APP.<verb>(...)`);
  - Express `req.query/body/params/cookies/headers`.
- Classes: CWE-89, 78, 22, 502 and 918. Each has, per language:
  - sinks: the tainted argument is marked `$SINK`, and the rule focuses on it;
  - sanitizers;
  - a confidence: `high` when the sink is an exact API, `medium` when only a method name on any receiver matches (`$DB.query`).
- `taint.py` checks the catalogue strictly: unknown or missing keys, CWE form, unique ids, non-empty sinks, and exactly one of `patterns` / `handler_parameter` per source.

**Rules** `taint_rules.yaml`, generated by `python -m riskgraph.modules.scanners.semgrep.taint` and committed.
- One rule per (language, class), id `riskgraph.taint.<language>.<class>`.
- Fields: `mode: taint`, severity ERROR, and metadata `cwe`, `confidence`, `source: riskgraph`, `license: Apache-2.0`, `analysis: intraprocedural`.
- No YAML anchors.
- A test fails when the committed file differs from what the catalogue generates.

**Wiring.** The setting `semgrep_taint_rules_path` adds a second `--config` to the Semgrep command. It defaults to unset (off).
- The rules have only been checked structurally here. One rule Semgrep refuses fails the whole Semgrep run, and with it every SAST finding of every scan.
- The owner runs them against the real Semgrep (L-4), copies the file into the scanner image, and decides whether to turn them on by default (F-2-1).

**Taint finding contract.**
- **Redaction.** Before snippet keys are dropped, `dataflow_trace` becomes `riskgraph_taint_steps`: file, line and role (source, step, sink), never code.
  - Consecutive repeats are collapsed.
  - At most 50 steps; the sink is kept when the trace is capped.
  - A malformed trace gives fewer steps, never an error.
- **Parsing.** A `riskgraph.taint.*` hit is `source_type = sast` with `attrs.analysis = "intraprocedural"` and `attrs.taint_steps`. The parser rebuilds each step from the stored report with type checks, and normalizes the paths.
- **Evidence.** The hit's member record has kind `taint_flow`, assurance **`inferred`** and the steps as `FlowStep`s: a rule applied to parsed code inside one function, with a catalogue that can miss a sanitizer. It is never `verified` in tier 1.
- **Correlation.**
  - A tier-1 hit joins a generic SAST finding at the same file and line whose primary CWE is in the same family: 89 ⊇ {564, 943}; 78 ⊇ {77}; 22 ⊇ {23, 36, 73}; 502; 918.
  - The result is one finding with both occurrences.
  - The generic finding's merge key is kept, so findings that already exist keep their identity across scans. A tier-1 hit with no generic partner keeps its own key (file, line, CWE).
  - Corroboration K counts distinct scanners, so two Semgrep rules leave K at 1. The plan's "K applies" holds when tier 2 (Joern, another engine) joins in X4 part 2.

**Suite** `backend/evaluation/taint_suite.py`: plan §6's 40 cases (5 classes × intraprocedural / cross-function / cross-file / sanitized × Python and JS) generated as code with labels and a marked sink line, plus a scorer from Semgrep JSON to recall per variant, precision and the sanitized-flag rate.

## Consequences
- (+) Tier 1 and tier 2 will read one catalogue, so they cannot drift.
- (+) A taint finding shows its path from source to sink without storing any code.
- (−) No recall is claimed. By construction, tier 1 can only find the intraprocedural cases; the measured numbers come from L-4.
- (−) The trace shape (`CliLoc`, `CliCall`, `intermediate_vars`) is from Semgrep's documented JSON as I remember it (BELIEVE). The walker accepts any location-shaped dict, so a shape change costs steps, not findings.
- (−) Name-based sources (`request.GET`, `req.query`) miss renamed objects; under-claiming is the rule.
- (−) Until F-2-1 is answered, a default scan is unchanged: no tier-1 findings.

## Rejected
- **Adapting rules from `semgrep-rules`.** Forbidden by G12 and plan §8 decision 6.
- **Hand-written rule files.** Two tiers would need to stay in step by hand.
- **Turning tier 1 on by default now.** It is unverified against the real engine, and the failure mode (no SAST findings at all) is worse than not having tier 1.
- **Changing generic SAST merge keys to CWE families.** It would re-key existing findings and break their history.
